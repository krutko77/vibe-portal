01Структура папки

Всё, что настраивает поведение Claude в проекте, лежит в .claude/. Рядом — CLAUDE.md (память) и .mcp.json (внешние инструменты).

ПАПКА КЛОДА/ ├── CLAUDE.md # память и правила проекта ├── index.html # эта страница ├── .mcp.json # MCP-серверы (общие для команды) └── .claude/ ├── settings.json # права, хуки, тумблеры MCP ├── settings.local.json.example # пример личных настроек ├── skills/ # навыки │ ├── superpowers/ # процессные скиллы │ └── ui-ux-pro-max/ # дизайн-интеллект ├── commands/ # слэш-команды │ ├── prototype-first.md │ └── explain-claude.md ├── agents/ # субагенты │ └── ui-prototyper.md ├── hooks/ # скрипты на события │ └── session-start.sh └── output-styles/ # стили вывода └── tutor.md

02Сущности и за что отвечают

Каждая папка внутри .claude — отдельный тип расширения Claude Code.

📄 CLAUDE.md память

Грузится в контекст всегда. Правила, договорённости, контекст проекта.

🧠 skills навыки

Переиспользуемые инструкции «как делать X». Файл SKILL.md в папке навыка. Вызываются по запросу.

⌨️ commands /команды

Слэш-команды. Markdown с frontmatter в commands/имя.md → вызов /имя.

🤖 agents субагенты

Отдельный исполнитель со своим набором инструментов и чистым контекстом.

🪝 hooks события

Скрипты на SessionStart, PreToolUse и др. Запускает сам harness, а не модель.

🎨 output-styles тон

Меняют манеру ответов Claude (например режим «Наставник»).

🔌 .mcp.json инструменты

Подключение внешних MCP-серверов: Figma, Pencil, Playwright, Context7…

⚙️ settings.json настройки

Права (permissions), переменные окружения, хуки, тумблеры MCP-серверов.

03Из чего состоит CLAUDE.md

Обычный Markdown — но Claude читает его как системные инструкции проекта. Чёткой схемы нет, но удачный файл содержит блоки:

БлокЗачем
Назначение проектаЧто это и для чего — пара строк сверху.
Структура / навигацияГде что лежит, ключевые файлы и папки.
Правила работыДоговорённости: «сначала прототип», «секреты — мимо репо» и т.п.
Команды и инструментыКак запускать, какие MCP подключены.
Стиль и ограниченияЧего делать не нужно, на каком языке отвечать.
Иерархия памяти. Claude объединяет ~/.claude/CLAUDE.md (глобально, для всех проектов) и ./CLAUDE.md (этот проект). Локальный дополняет и переопределяет глобальный.

04Что такое MCP

MCP (Model Context Protocol) — стандарт, по которому Claude подключается к внешним «серверам инструментов». Каждый сервер добавляет набор инструментов: Figma даёт доступ к дизайну, Pencil — к прототипам, Playwright — к браузеру.

Конфигурация в проекте — файл .mcp.json. Он коммитится и шарится на всю команду. Секреты в него не пишут — подставляют через переменные окружения.

// .mcp.json — подключение MCP-сервера Figma
{
  "mcpServers": {
    "figma": {
      "command": "npx",
      "args": ["-y", "figma-developer-mcp", "--stdio"],
      "env": { "FIGMA_API_KEY": "${FIGMA_API_KEY}" }
    }
  }
}
ПолеЧто значит
commandЧем запустить сервер (обычно npx).
argsАргументы запуска, в т.ч. имя пакета сервера.
envПеременные окружения сервера — сюда идут токены через ${...}.

05Как подключить MCP-сервер

На примере Figma. Аналогично для Pencil, Playwright, Context7.

  1. Получить токен. Figma → Settings → Security → Personal access tokens → создать токен.
  2. Положить токен в окружение. В ~/.zshrc: export FIGMA_API_KEY="figd_..." и перезапустить терминал.
  3. Описать сервер в .mcp.json. Блок mcpServers.figma как в примере выше.
  4. Разрешить сервер. В .claude/settings.json добавить имя в enabledMcpjsonServers.
  5. Перезапустить Claude Code. Проверить статус командой /mcp — сервер должен быть connected.
Альтернатива через CLI: claude mcp add figma -- npx -y figma-developer-mcp --stdio — добавит сервер без ручного редактирования JSON.

06Каждая сущность подробно

Переключай вкладки. По каждой: что это, где лежит, пример и как применять в жизни.

🧠 Skills — навыки

Переиспользуемый «рецепт», который объясняет Claude как делать X: пошаговый процесс, правила, чек-листы. Claude подгружает скилл только когда он нужен (по описанию в description), а не держит в контексте всегда — это экономит память.

Где: .claude/skills/<имя>/SKILL.md Формат: Markdown + frontmatter Вызов: авто по смыслу или /имя
Пример — SKILL.md
---
name: commit-style
description: Use when writing git commits — формат и правила сообщений
---

# Стиль коммитов

1. Заголовок ≤ 50 символов, в повелительном наклонении.
2. Пустая строка, затем тело: что и зачем, не «как».
3. Внизу ссылка на задачу: Refs: JIRA-123.
Как применять в жизни
  • Онбординг правил команды. Завернул «как мы пишем тесты / коммиты / PR» в скилл — и Claude соблюдает их сам, без напоминаний в каждом чате.
  • Сложный повторяемый процесс. «Деплой на прод», «миграция БД», «разбор инцидента» — один раз описал шаги, дальше вызываешь по имени.
  • В этом проекте: superpowers даёт скиллы brainstorming, test-driven-development, systematic-debugging; ui-ux-pro-max — выбор стиля, палитры и шрифтов под задачу.

⌨️ Команды — слэш-команды

Готовый шаблон запроса, который запускается командой /имя. Удобно для действий, которые повторяешь часто и хочешь звать одним словом. Аргументы подставляются через $ARGUMENTS.

Где: .claude/commands/<имя>.md Формат: Markdown + frontmatter Вызов: /имя аргументы
Пример — commands/review.md
---
description: Ревью текущих изменений по нашему чек-листу
argument-hint: [папка или файл]
allowed-tools: Read, Grep, Bash(git diff:*)
---

Проверь изменения в $ARGUMENTS на: баги, безопасность,
читаемость. Дай список замечаний с приоритетами.
Как применять в жизни
  • Частые рутины одной командой. /review, /changelog, /translate — не печатаешь длинный промпт каждый раз.
  • Единый процесс для всей команды. Команда лежит в репозитории → у всех одинаковый /deploy или /new-component.
  • В этом проекте: /prototype-first — UI сначала прототипом в Pencil, потом код; /explain-claude — объясняет структуру папки.

🔌 MCP — внешние инструменты

Model Context Protocol — способ подключить к Claude внешние «серверы инструментов». Каждый сервер добавляет реальные действия: Figma — читать/писать дизайн, Pencil — собирать прототипы, Playwright — управлять браузером, Context7 — свежая документация.

Где: .mcp.json (корень проекта) Формат: JSON Статус: команда /mcp
Пример — .mcp.json
{
  "mcpServers": {
    "playwright": {
      "command": "npx",
      "args": ["-y", "@playwright/mcp@latest"]
    },
    "figma": {
      "command": "npx",
      "args": ["-y", "figma-developer-mcp", "--stdio"],
      "env": { "FIGMA_API_KEY": "${FIGMA_API_KEY}" }
    }
  }
}
Как применять в жизни
  • Дизайн → код. Кидаешь ссылку на макет Figma — Claude читает его через MCP и верстает близко к оригиналу.
  • Проверка живого сайта. Playwright MCP открывает страницу, кликает, снимает скриншот — Claude видит результат, а не догадывается.
  • Свежие доки. Context7 подтягивает актуальную документацию библиотеки, чтобы код не опирался на устаревшие знания модели.
  • Секреты — через env и ${...}, а не текстом в файле: .mcp.json коммитится в репозиторий.

🤖 agents/ — субагенты

Отдельный «работник» со своим набором инструментов и чистым контекстом. Главный Claude поручает ему узкую задачу, тот выполняет и возвращает только результат — основной диалог не засоряется деталями. Можно запускать несколько параллельно.

Где: .claude/agents/<имя>.md Формат: Markdown + frontmatter Вызов: авто или явно «через субагента»
Пример — agents/ui-prototyper.md
---
name: ui-prototyper
description: Быстрая сборка UI-прототипов в Pencil (.pen)
tools: mcp__pencil__batch_design, mcp__pencil__get_screenshot, Skill
model: sonnet
---

Ты — узкий субагент-прототайпер. По описанию экрана собери .pen
и верни путь к файлу + скриншот. Не пиши длинных сообщений.
Как применять в жизни
  • Тяжёлый поиск по кодовой базе. Субагент перелопачивает сотни файлов и отдаёт вывод — главный контекст остаётся чистым.
  • Параллельные варианты. Запустил трёх ui-prototyper — получил 3 наброска экрана одновременно.
  • Ограничение прав. Субагенту-ревьюеру даёшь только Read/Grep — он физически не сможет что-то изменить.

🪝 hooks/ — реакции на события

Shell-команды, которые сам Claude Code (не модель!) запускает на событие: старт сессии, перед/после вызова инструмента, остановка. Поэтому хуки — для гарантированных действий, которые должны срабатывать всегда.

Где: .claude/hooks/ + регистрация в settings.json Формат: любой исполняемый скрипт События: SessionStart, PreToolUse, PostToolUse, Stop…
Пример — авто-форматирование после правки файла
// .claude/settings.json
"hooks": {
  "PostToolUse": [{
    "matcher": "Edit|Write",
    "hooks": [{ "type": "command",
      "command": "npx prettier --write \"$CLAUDE_FILE_PATHS\"" }]
  }]
}
Как применять в жизни
  • Авто-формат и линт. После каждого Edit прогоняется Prettier/ESLint — код всегда причёсан.
  • Защита от опасного. PreToolUse блокирует rm -rf или правку .env до выполнения.
  • Контекст на старте. SessionStart печатает правила проекта — как session-start.sh в этом проекте.
  • Уведомления. На Stop — звук или сообщение в Slack «задача готова».

🎨 output-styles/ — стиль ответов

Меняют манеру и тон, в котором Claude отвечает, не трогая саму логику работы. Один и тот же запрос можно получить «по-инженерному кратко» или «как от наставника с пояснениями».

Где: .claude/output-styles/<имя>.md Формат: Markdown + frontmatter Вызов: команда /output-style
Пример — output-styles/tutor.md
---
name: Наставник
description: Объясняет каждый шаг простыми словами
---

Перед действием говори ЧТО и ЗАЧЕМ делаешь.
После — что получилось и как проверить.
Добавляй врезки «💡 Почему так».
Как применять в жизни
  • Обучение. Режим «Наставник» — джуниор видит не только результат, но и рассуждения.
  • Скорость для своих. Сжатый стиль без воды, когда нужен только diff и команды.
  • Под аудиторию. Демо клиенту — больше объяснений; внутренняя работа — сухие факты.

⚙️ settings.json — настройки проекта

Главный конфиг поведения Claude в проекте: права (что можно без спроса, что спросить, что запретить), переменные окружения, регистрация хуков и тумблеры MCP-серверов. Личное (не для репозитория) выносят в settings.local.json.

Где: .claude/settings.json Формат: JSON Личное: settings.local.json (в .gitignore)
Пример — settings.json
{
  "permissions": {
    "allow": ["Read", "Bash(git diff:*)"],
    "ask":   ["Bash(git push:*)"],
    "deny":  ["Read(./.env)"]
  },
  "enabledMcpjsonServers": ["figma", "pencil"]
}
Как применять в жизни
  • Меньше лишних вопросов. Безопасное (Read, git diff) в allow → Claude не дёргает разрешением на каждом шаге.
  • Подушка безопасности. git push в ask, .env в deny → опасное не уйдёт незаметно.
  • Общие правила команды. settings.json в репо — у всех одинаковые права; личные исключения каждый держит в своём settings.local.json.

🙈 .gitignore — что не коммитить

Список файлов и папок, которые git игнорирует. В контексте Claude важен, чтобы в репозиторий не утекли секреты и личные настройки, и чтобы не тащить мусор.

Где: .gitignore (корень) Формат: по строке на шаблон Действие: исключает из git
Пример — .gitignore
# Личные настройки Claude — у каждого свои
.claude/settings.local.json

# Секреты
.env
*.key

# Системное
.DS_Store
node_modules/
Как применять в жизни
  • Не утекут токены. .env и ключи остаются только на твоей машине.
  • Личное отдельно от общего. settings.local.json игнорируется, а общий settings.json — коммитится.
  • Чистый репозиторий. Без node_modules/ и .DS_Store история не засоряется.
