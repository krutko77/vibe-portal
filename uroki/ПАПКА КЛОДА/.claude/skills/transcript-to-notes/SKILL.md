# Транскрибация → иллюстрированный конспект

Превращаешь сырой текст расшифровки в **структурированный конспект с Mermaid-диаграммами**
и сохраняешь его **в двух форматах**: `*.md` (для GitHub/Obsidian/Notion) и `*.html`
(самодостаточная страница, диаграммы рендерит mermaid.js с CDN).

## Вход

Пользователь даёт транскрибацию — как текст в сообщении или как путь к файлу
(`.txt`/`.md`/`.vtt`/`.srt`). Если это субтитры (`.vtt`/`.srt`) — сначала убери
таймкоды и номера реплик, склей в связный текст.

Если расшифровки нет в сообщении и путь не указан — **спроси**, где она.

## Процесс

1. **Прочитай и пойми** весь транскрипт. Определи тему, аудиторию, главную мысль.
2. **Построй структуру конспекта** (см. шаблон ниже). Не пересказывай дословно —
   выделяй тезисы, убирай слова-паразиты, воду и повторы устной речи.
3. **Подбери диаграммы** под содержание (см. «Какую диаграмму выбрать»). Минимум
   **одна** диаграмма; для длинного материала — 2–4 разных типов. Не вставляй
   диаграмму ради галочки — только если она реально проясняет структуру/процесс/связи.
4. **Сгенерируй Markdown** по шаблону.
5. **Сгенерируй HTML** из того же содержания по шаблону `assets/template.html`
   (подставь заголовок, оглавление и тело; Mermaid-блоки оставь как `<pre class="mermaid">`).
6. **Сохрани оба файла** рядом: `<slug>.md` и `<slug>.html`, где `slug` —
   короткое имя темы латиницей-кебабом (напр. `react-hooks-lecture`).
7. **Покажи пользователю** путь к файлам и краткое содержание (оглавление).
   При наличии Playwright MCP — предложи открыть HTML и снять скриншот для проверки.

## Шаблон конспекта (Markdown)

```markdown
# <Заголовок темы>

> **TL;DR.** 2–3 предложения — суть всего материала.

## 📑 Оглавление
- ссылки на разделы

## 🗺️ Карта темы
<здесь Mermaid-диаграмма верхнего уровня: mindmap или flowchart>

## 1. <Раздел>
- ключевой тезис
- ключевой тезис
  > 💬 Цитата/важный момент из расшифровки (если есть)

## 2. <Раздел>
...

## 🔑 Ключевые термины
| Термин | Определение |
|---|---|

## ✅ Главные выводы
- вывод 1
- вывод 2

## ❓ Вопросы для самопроверки
- вопрос 1
- вопрос 2
```

## Какую диаграмму выбрать (Mermaid)

| Содержание материала | Тип диаграммы |
|---|---|
| Обзор темы, ветвление подтем | `mindmap` |
| Процесс, алгоритм, «шаг за шагом» | `flowchart TD` |
| Хронология, история, этапы во времени | `timeline` |
| Взаимодействие сторон/сервисов/людей | `sequenceDiagram` |
| Состояния и переходы | `stateDiagram-v2` |
| Структура сущностей и связи | `erDiagram` или `classDiagram` |
| Доли, распределение | `pie` |

## Правила Mermaid (чтобы не падал рендер)

- Текст узлов с пробелами/кириллицей — в кавычках: `A["Текст узла"]`.
- Не используй внутри меток символы `()`, `[]`, `{}`, `;`, `#` без кавычек.
- Стрелки flowchart: `-->`, с подписью: `A -->|"да"| B`.
- В `mindmap` — отступы строго пробелами (не табами), корень один.
- Один тип диаграммы на один блок ` ```mermaid `.
- Подробные правила и примеры — в `references/mermaid-rules.md`.

## Вывод

- Markdown: Mermaid в блоках ` ```mermaid … ``` ` (рендерится на GitHub/Obsidian).
- HTML: те же диаграммы в `<pre class="mermaid">…</pre>`, библиотека подключена в шаблоне.
- Картинки — **только Mermaid-диаграммы**, растровые изображения не вставляем.

> Для рендера Mermaid в PNG/SVG (если попросят файлы-картинки) используй
> `npx -y @mermaid-js/mermaid-cli -i diagram.mmd -o diagram.png`.
