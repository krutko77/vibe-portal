# Сначала прототип (prototype-first)

Ты работаешь в режиме **«сначала прототип»**. Пользователь просит: **$ARGUMENTS**

Действуй строго по шагам и **не пиши финальный продакшн-код, пока прототип не одобрен**.

## Правила

1. **Никаких действий с сайтом/UI напрямую в коде.** Всё, что касается интерфейса,
   страниц, экранов и компонентов — сначала собирается как **прототип в Pencil** (`.pen`).
2. Перед проектированием подключи дизайн-интеллект: вызови скилл
   `ui-ux-pro-max` (`Skill` → `ui-ux-pro-max:ui-ux-pro-max`), чтобы выбрать стиль,
   палитру, шрифты и UX-паттерны под задачу.
3. Используй **только инструменты `pencil` MCP** для чтения и записи `.pen`:
   - `get_editor_state` — понять текущее состояние редактора;
   - `open_document('new')` — создать новый `.pen`, если активного нет;
   - `get_guidelines` — загрузить гайдлайны Pencil;
   - `batch_design` — собрать прототип операциями `I/C/R/U/...`;
   - `get_screenshot` — снять скриншот готового прототипа.
4. **Покажи прототип пользователю** (скриншот через `get_screenshot`) и
   **дождись явного одобрения**.
5. Только после «ок» переходи к реализации в коде — и реализуй пиксель-в-пиксель
   по утверждённому прототипу.

## Порядок выполнения

1. Уточни 1–2 ключевых требования, если задача размыта.
2. `Skill ui-ux-pro-max` → собери дизайн-направление (стиль + палитра + шрифты).
3. `get_editor_state` → при необходимости `open_document('new')`.
4. `batch_design` → собери экран(ы) прототипа.
5. `get_screenshot` → покажи результат и спроси одобрение.
6. После одобрения — реализация в коде.

> Если пользователь просит «сразу код» — напомни про режим прототипа и предложи
> быстрый набросок прототипа (1 экран) прежде чем кодить.
