Деплой es-trans_repairs — инструкция для агента
================================================

Домен repairs.es-trans.ru уже зарегистрирован в deploy-service.
Не проси root, sudo или пароль к 201.51.4.183 — это тот же хост, что
держит весь портал, доступ туда закрыт намеренно.

1. Создай .vibe-deploy.json в корне проекта
--------------------------------------------
{ "domain": "repairs.es-trans.ru" }

(домен менять после регистрации нельзя — сервис откажет)

2. Вызови деплой
-----------------
curl -X POST http://172.30.0.1:8191/deploy \
  -H 'Content-Type: application/json' \
  -d '{"project":"es-trans_repairs"}'

(project — имя папки проекта ровно как в /home/my_workspace)

3. Что произойдёт дальше
--------------------------
Автоматически, в этом порядке:
  rsync кода (кроме node_modules/.git/.env)
  -> npm install --omit=dev
  -> pm2 restart

Ответ (пример):
{
  "domain": "repairs.es-trans.ru",
  "url": "https://repairs.es-trans.ru/",
  "slug": "es-trans-repairs",
  "port": 3003,
  "firstRun": false
}

4. Если что-то пошло не так
-----------------------------
403 — контейнер не распознан сервисом (редкий случай), сообщи админу,
      не пытайся обойти.
400 — смотри поле "error" в ответе, там по делу написано, что не так
      (нет .vibe-deploy.json, домен не совпадает и т.п.).

5. Чего не делать
-------------------
Не проси root/sudo/пароль к 201.51.4.183 — доступ закрыт намеренно.
Не трогай .env на проде через деплой — он туда не попадает и не
перезаписывается; смена переменных окружения на сервере — ручная
операция, не через этот сервис.

Контракт задокументирован в CLAUDE.md (раздел «Деплой на этот же
хост для проектов из /home/my_workspace») и docs/decisions.md (D-004/D-005).
