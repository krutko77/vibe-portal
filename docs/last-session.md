## Ключевые решения
- Для прогресса загрузки выбран `XMLHttpRequest` вместо `fetch` —
  единственный API в браузере, который даёт `upload.onprogress` с
  `loaded`/`total`; `fetch` в текущей спецификации не предоставляет такой
  возможности для тела запроса при отправке (только для чтения ответа).
- Правка статуса `es-trans_PDn` сделана прямо, без `AskUserQuestion` —
  формат и последствия идентичны трём уже применённым ранее в этом же
  проекте (низкий риск, чисто визуальный override в панели, не влияет на
  деплой/данные).

## Подводные камни
- **`fetch` не даёт прогресса отправки тела запроса.** Если понадобится
  индикация прогресса для другой формы загрузки в этом проекте (например,
  `/api/project-chat/upload` для вложений в чат) — та же проблема, то же
  решение: переход на `XMLHttpRequest` для конкретно этого запроса, не
  обязательно переписывать весь модуль.
- Прогресс-бар показывает прогресс **отправки** (upload), а не обработки
  на сервере (`createUploadedProject` — копирование/распаковка на
  бэкенде). Для маленьких проектов разница незаметна, но для проекта у
  верхней границы лимита (90 MB) полоса может дойти до 100% раньше, чем
  реально появится новый проект в списке — это ожидаемо, не баг.
