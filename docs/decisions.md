## D-001 — chat-history как проектный скилл, не глобальный (2026-07-21)

**Контекст:** нужен был скилл для экспорта истории сессий Claude Code в читаемый Markdown.
**Варианты:** глобальный скилл (`~/.claude/skills/`, доступен в любом проекте) или проектный (`.claude/skills/`, только в vibe-portal).
**Решение:** проектный, вывод — в `.claude/chat-history/` (добавлено в `.gitignore`).
**Почему:** пользователь явно выбрал ограничить область vibe-portal; личный рабочий лог не должен уходить в git/бэкап-снапшот кодовой базы.
**Последствия:** в других проектах скилл придётся ставить заново; экспортированные `.md` не коммитятся и не бэкапятся общим `backup-all.sh` (в текущей конфигурации).

## D-002 — установка команд /end, /decision, /handoff, /log из репозитория ученика курса (2026-07-21)

**Контекст:** ученик курса (`krutko77`, есть в `users-vibe.json`) поделился ссылкой на свой репозиторий `github.com/krutko77/scills-claude` с набором Claude-команд для журналирования сессий.
**Варианты:** установить не глядя; отказаться, т.к. источник — ученик, а команды исполняются в хостовой admin-сессии с полными правами; прочитать содержимое каждого файла перед установкой и решить по факту.
**Решение:** каждый файл (`end.md`, `decision.md`, `handoff.md`, `log.md`) прочитан целиком перед установкой. Подозрений не подтвердилось — только чтение/запись `docs/*` и `git commit` через `scripts/snapshot.sh`, ни сетевых вызовов, ни обращения к секретам. Установлены как команды `.claude/commands/*.md`, под них создана инфраструктура `docs/state.md`, `docs/changelog.md`, `docs/last-session.md`, `docs/handoff.md`, `docs/decisions.md`, `scripts/snapshot.sh`.
**Почему:** содержимое безопасно и полезно (дисциплина хендоффа между сессиями); риск не в конкретных файлах, а в бесконтрольной установке кода с любого внешнего источника — этот риск закрыт построчным ревью перед установкой, а не отказом.
**Последствия:** `scripts/snapshot.sh` делает `git add -A` — перед первым запуском любой из команд (`/end`, `/log`, `/handoff`, `/decision`) стоит проверять `git status`, чтобы случайно не закоммитить что-то лишнее из untracked.

## D-003 — фикс изоляции vibe-net: динамическое имя моста вместо переименования интерфейса (2026-07-22)

**Контекст:** `scripts/setup-iptables.sh` хардкодил `BR="br-vibe"`, а реальный bridge-интерфейс сети `vibe-net` называется `br-92be0fc90d9e` (docker сам генерит имя как `br-<первые 12 hex ID сети>`, кастомное имя через `com.docker.network.bridge.name` никогда не было выставлено). Итог: правила `VIBE-FILTER`/`VIBE-INPUT` не матчали ни один пакет — изоляция между контейнерами учеников и блок доступа к хостовым сервисам не работали (0 pkts на всех правилах).
**Варианты:** (1) переименовать живой интерфейс `ip link set br-92be0fc90d9e name br-vibe`, как было предварительно записано в CLAUDE.md; (2) поправить `setup-iptables.sh`, чтобы имя моста вычислялось из `docker network inspect vibe-net` при каждом запуске.
**Решение:** вариант (2).
**Почему:** имя интерфейса живёт только в ядре и не персистентно — docker создаёт bridge заново с дефолтным именем `br-<ID>` при пересоздании сети или после ребута хоста (интерфейсы не переживают перезагрузку). Ручной `ip link set` дал бы правильный результат прямо сейчас, но тихо откатился бы при следующей перезагрузке сервера, а systemd-юнит `vibe-iptables.service` как раз и гоняется `After=docker.service` при каждой загрузке — баг вернулся бы без явных симптомов. Динамическое определение имени устойчиво к ребуту и пересозданию сети, не трогает живую сеть контейнеров вообще (только правила iptables, что и так штатно идемпотентно).
**Последствия:** после правки пришлось вручную снять старые hook-правила в `DOCKER-USER`/`INPUT` (ссылались на несуществующий `br-vibe`, из-за чего `iptables -D` по новому имени их не находил и `vibe-iptables.service` падал с "CHAIN_DEL failed: Device or resource busy") — разовая ручная чистка, дальше юнит идемпотентен сам по себе. Проверено практически на `vibe-krutko77`: shim (172.30.0.1:8190) доступен, хостовый порт :3020 и публичный IP хоста — задропаны, внешний интернет — доступен; счётчики пакетов в `VIBE-FILTER`/`VIBE-INPUT` подтверждают срабатывание нужных правил.
