# Спек: хаб «База знаний» — объединение «Курс» + «Материалы»

Дата: 2026-06-04 · Статус: на ревью · Прототип: https://vibe.kiselevgroup.com/proto-materials

## Проблема

Материалы курса размазаны по трём местам, и ученики путаются «где что смотреть»,
а добавлять новое неудобно:

1. Вкладка **«Курс»** — модули/уроки. Структура (`COURSE`) и тела уроков —
   в коде ([app.js](../../../panel/public/js/app.js), [lessons-m1.js](../../../panel/public/js/lessons-m1.js)).
   Материалы/домашки модуля сейчас — просто текстовые строки, не файлы.
2. Вкладка **«Материалы»** — 7 захардкоженных подвкладок в [index.html](../../../panel/public/index.html)
   (Инструкция, Шпаргалка, Шаблоны, Публикация, Скиллы, Ссылки, FAQ).
3. Папка `uroki/` в корне репо — учебные мини-сайты, которым негде разместиться.

## Цель

Один хаб **«База знаний»** вместо двух вкладок. Слева — сайдбар из 4 групп
(порядок утверждён в прототипе):

1. **База знаний** → «С чего начать» (онбординг).
2. **Справочник** → шпаргалки, примеры/мини-сайты, шаблоны, ссылки, скиллы, FAQ.
3. **Материалы уроков** → сквозной вид: «Все материалы», «Все домашки»,
   «Все мастер-классы» — по всем модулям сразу.
4. **По модулям** → Модуль 1…N, внутри каждого секции материалы / домашки /
   мастер-классы (+ конспекты уроков, как сейчас).

Сверху — общий поиск. Добавление нового материала = я (Claude) дописываю **один
объект в реестр** + (если есть тело) кладу файл в `content/`. Он сам появляется
и в своём модуле, и в сквозном виде.

## Не-цели (YAGNI)

- Нет формы-админки для добавления (решено: добавляем через Claude).
- Нет видео-хостинга — мастер-классы это ссылка на запись + текстовый конспект.
- Нет прав/видимости на отдельные материалы — всё видно любому залогиненному
  ученику (как сейчас «Курс»/«Материалы»). Admin-гейта на материалы нет.
- Не трогаем VS Code, Проекты, публикацию, шим, изоляцию.

## Что переиспользуем (важно — не переписывать)

- `COURSE` (массив 6 модулей с уроками/материалами/домашками/мит-апами) —
  остаётся источником структуры курса. Выносим из `app.js` в отдельный
  `panel/public/js/course-data.js` (чтобы редактировать, не трогая логику).
- `lessons-m1.js` — тела уроков. Остаётся; в перспективе тела переезжают в
  `content/` пофайлово, но это можно отложить (см. этапы).
- Рендер карточек/страниц переиспользует существующие классы портала
  (`.page-h1`, `.ms-grid`, `.dl-card`, `.link-tile`, `.course-module` и пр.) —
  прототип уже доказал, что они дают «родной» вид.

## Модель данных — единый реестр

Два редактируемых источника (оба — «одно аккуратное место»):

### 1. `course-data.js` — структура курса (уже есть как `COURSE`)
Без изменений по форме. Модуль:
```js
{ id:'m1', title:'…', lessons:[{id:'l1',title:'…'}], materials:[…], homework:[…], meetup:{…}, bonus?:{…} }
```
Уточнение: `materials`/`homework` сейчас строки. Расширяем до **массива
объектов-материалов того же формата, что `reference.js`** (см. ниже), —
чтобы можно было привязать файл/ссылку/тело, а не только текст. Поля `kind`
и `module` у них проставляются автоматически из контекста модуля. Обратная
совместимость: если осталась строка — рендерим как описание-заглушку.

### 2. `reference.js` — реестр внемодульных материалов (новое)
Массив объектов одного формата (он же используется для секций модуля):
```js
{
  id:        'cheatsheet-claude-code',   // уникальный, = имя папки в content/ если есть тело
  kind:      'cheatsheet',               // start|cheatsheet|example|template|link|skill|faq
                                         // (для модульных: material|homework|masterclass)
  module:    null,                       // номер модуля для модульных, иначе null
  icon:      '📋',
  title:     'Шпаргалка по Claude Code',
  desc:      'Горячие клавиши, slash-команды, флаги CLI.',
  isNew:     false,
  due:       null,                       // дедлайн для домашек
  body:      'html',                     // 'html' → content/<id>/body.html; null → нет тела
  href:      null,                       // внешняя ссылка (для kind=link/skill)
  download:  null,                       // 'zip' → content/<id>/site/ отдаётся .zip
}
```

`kind` определяет, в какую группу сайдбара попадёт материал:
- `start` → «База знаний / С чего начать»;
- `cheatsheet|example|template|link|skill|faq` → «Справочник»;
- `material|homework|masterclass` (+ `module`) → «По модулям» и «Материалы уроков».

## Хранилище контента — `content/`

Новый каталог в репо (рядом с `templates/`):
```
content/
├── reference.js                  реестр внемодульных материалов
├── <id>/                         папка материала, если у него есть тело/файлы
│   ├── body.html                 HTML-фрагмент (гайд, шпаргалка, описание ДЗ)
│   └── site/                     мини-сайт/пример целиком (для kind=example) — отдаётся .zip
└── …
```
`uroki/клод мд` и `uroki/ПАПКА КЛОДА` переезжают в `content/example-md-claude/site/`
и `content/example-claude-folder/site/` соответственно; в `reference.js` — по
объекту `kind:'example'`. Папка `uroki/` из корня удаляется.

## API (panel/lib/kb.js + роуты в server.js)

Все — `requireAuth` (как «Курс»/«Материалы» сейчас за логином):
| Метод | Путь | Описание |
|-------|------|----------|
| GET | `/api/kb` | объединённый манифест: `COURSE` + `reference.js` → JSON для рендера сайдбара и карточек |
| GET | `/api/kb/:id/body` | HTML-тело материала из `content/<id>/body.html` |
| GET | `/api/kb/:id/download` | zip из `content/<id>/site/` (переиспользуем системный `zip`, как в `template-download`) |

Тела уроков (`lessons-m1.js`) на первом этапе остаются клиентскими; позже
`l['m1.l1']` → `content/m1-l1/body.html` через тот же `/api/kb/:id/body`.

## Фронтенд

- **Навбар** ([index.html](../../../panel/public/index.html)): два таба `Курс` + `Материалы` →
  один `База знаний` (`data-view="kb"`). Иконка — книга. Остаются VS Code, Проекты.
- **Новая секция** `view-kb`: разметка хаба (сайдбар + контент + поиск), 1:1 с
  прототипом [proto-materials.html](../../../panel/public/proto-materials.html).
- **Новый модуль** `panel/public/js/kb.js` (по образцу логики прототипа): грузит
  `/api/kb`, рендерит 4 группы сайдбара в утверждённом порядке, обрабатывает
  клики/поиск, подтягивает тела через `/api/kb/:id/body`. Состояние выбора — в
  `localStorage` (как `courseSelected`). Дефолт — «С чего начать».
- Старые `view-course` и `view-materials` секции и их JS удаляются; полезная
  логика рендера уроков переносится в `kb.js`.
