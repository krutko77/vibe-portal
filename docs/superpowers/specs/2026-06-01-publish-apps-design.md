# Публикация приложений учеников — дизайн

**Дата:** 2026-06-01
**Проект:** vibe-portal
**Статус:** утверждён, готов к плану реализации

## Цель

Дать каждому ученику возможность публиковать свои приложения по URL
`https://vibe.kiselevgroup.com/<user>/<project>/`, доступному только
авторизованным. По умолчанию приложение видят владелец и админ; в настройках
можно открыть всем залогиненным. Админ видит все приложения. В таблице проектов
появляются иконка-ссылка и кнопка управления публикацией. У приложения есть
«деплой по умолчанию» — запуск без ручной настройки.

## Принцип работы

Приложение ученика запускается **внутри его контейнера** (как `student`,
uid 1000, в песочнице) на выделенном порту (3001+). Панель на хосте проксирует
запросы `/<user>/<project>/*` напрямую в `http://<IP-контейнера>:<порт>/` по
сети vibe-net. Проверено: хост (шлюз 172.30.0.1) достаёт контейнеры на
произвольном порту; наружу порты приложений **не публикуются**. nginx не
меняется — он уже шлёт весь трафик в панель (`location /`).

```
Браузер (авторизован)
  → nginx :443
  → vibe-panel :3020
      ├─ auth-гейт по сессии (visibility: owner|auth, админ — всё)
      ├─ ensure контейнер запущен + приложение живо (self-heal)
      └─ proxy → http://<containerIP>:<port>/  (strip префикса /<user>/<project>)
```

## Компоненты

### 1. Конфиг публикации — `.portal-meta.json` проекта

Источник истины (переживает рестарт панели/контейнера):

```json
{
  "publish": {
    "enabled": true,
    "visibility": "owner",        // "owner" = владелец+админ; "auth" = любой залогиненный
    "autosleep": true,            // true: засыпает с контейнером по idle, авто-оживает при заходе
                                  // false: контейнер не усыпляем, пока опубликовано
    "port": 3001,                 // выделенный порт внутри контейнера (per-container)
    "cmd": null                   // команда старта; null = автоопределение по стеку
  }
}
```

Поддержка нескольких приложений у одного ученика (1-5): у каждого проекта свой
порт. Порты локальны для контейнера (доступ по `containerIP:port`), глобальных
конфликтов нет. Аллокация: при включении публикации берём минимальный свободный
порт ≥ 3001 среди `publish.port` остальных проектов этого ученика.

### 2. Деплой по умолчанию (`panel/lib/publish.js`)

Автоопределение стека и команды старта:

- **Node** (есть `package.json`): энтрипоинт = `main` / цель `scripts.start` /
  первый из `src/server.js`, `server.js`, `index.js`, `app.js`.
  Запуск: `[ -d node_modules ] || npm install --no-audit --no-fund;
  exec env PORT=<port> node <entry>`.
- **PHP** (есть `www/` или `index.php`): docroot = `www` если есть, иначе корень.
  Запуск: `php -S 0.0.0.0:<port> -t <docroot>`.
- **Статика** (только `index.html`, нет package.json): `php -S 0.0.0.0:<port>`
  из корня проекта (php в образе будет — см. §8).
- Команду можно переопределить полем `publish.cmd` (на будущее; UI пока не даёт).

Запуск (детач, фоновый процесс = сам сервер, его pid в pidfile):

```
docker exec -d -u student -w <projectdir> vibe-<user> sh -lc '
  mkdir -p .publish
  [ -f package.json ] && [ ! -d node_modules ] && npm install --no-audit --no-fund >> .publish/app.log 2>&1
  nohup <cmd> >> .publish/app.log 2>&1 &
  echo $! > .publish/app.pid
'
```

`echo $!` пишет pid фонового сервера (node/php напрямую, без обёртки) в
`.publish/app.pid` → корректный kill при redeploy/stop. Логи — `.publish/app.log`
внутри проекта (отладка учеником/админом).

### 3. Жизненный цикл (self-healing) — `panel/lib/publish.js`

- **Включение публикации:** выделить порт, записать конфиг, запустить деплой.
- **Заход на URL** `/<user>/<project>/*`:
  1. auth-гейт (см. §4);
  2. `dockerStart(<user>)` если контейнер спит (как в `/code/`);
  3. проверка `containerIP:port` коротким HTTP/TCP-пробом; если не отвечает и
     `enabled` — (пере)запуск деплоя, поллинг до ~5 c;
  4. проксирование с обрезкой префикса `/<user>/<project>`;
  5. `touchActivity(<user>)` → держит контейнер 30 мин.
- **autosleep=false:** idle-reaper (`reapIdleContainers`) пропускает учеников,
  у которых есть проект с `publish.enabled && !autosleep`.
- **Redeploy:** убить старый pid (`kill $(cat .publish/app.pid)`), запустить заново.
- **Выключение публикации:** убить pid, `enabled=false`.

### 4. Доступ / auth-гейт

- `visibility="owner"` (дефолт): открыть может владелец проекта или админ.
- `visibility="auth"`: любой залогиненный ученик.
- Неавторизованный → 302 на `/` (логин). Публично-без-логина не делаем.
- Гейт — в middleware прокси-роута, до проксирования.

### 5. Роутинг и резерв имён

Публичный прокси-роут регистрируется в Express **после** `/api`, `/code`,
статики-ассетов, но как middleware, который активируется только если:
`seg1` есть в `users-vibe.json` И `seg2` — проект с `publish.enabled`. Иначе
`next()` (отдаём статику/404). Дополнительно — блоклист логинов при создании
ученика: `api, code, assets, css, js, img, public, well-known` (чтобы
`/<user>/` не затенял служебные пути). WebSocket-upgrade поддерживаем (как у
codeProxy) — на случай ws в приложениях.

**Ограничение подпути:** под `/<user>/<project>/` приложение должно использовать
**относительные** пути к ассетам/API (`css/...`, не `/css/...`), иначе ссылки
уйдут мимо приложения. Шаблон `_base` правим под относительные пути.

### 6. API панели

| Метод | Путь | Auth | Описание |
|-------|------|------|----------|
| GET | `/:user/:project/*` | session (visibility) | прокси в приложение, self-heal |
| GET | `/api/projects/:name/publish` | user (свой) | статус публикации (enabled, url, port, running) |
| POST | `/api/projects/:name/publish` | user (свой) | вкл/выкл + visibility + autosleep |
| POST | `/api/projects/:name/redeploy` | user (свой) | перезапуск процесса |

Админ может управлять чужими через `?asUser=` (паттерн уже есть в project-chat).

### 7. UI (`panel/public`)

В строке проекта добавляются две иконки рядом с существующими:

- 🔗 **ссылка** — если `publish.enabled`, открывает `/<user>/<project>/` в новой
  вкладке; иначе открывает модалку публикации.
- **«Публ.»** (иконка) → модалка `modal-publish`:
  - тумблер **Публикация** вкл/выкл;
  - **Кто может смотреть:** Владелец+админ / Все залогиненные;
  - **Авто-засыпание** вкл/выкл;
  - показ URL с кнопками «копировать»/«открыть»;
  - кнопка **«Передеплоить»**;
  - статус: запущено / спит, порт, ссылка на лог.

### 8. Образ контейнера — добавить PHP

`workspace-image/Dockerfile`: установить `php-cli` (и `psmisc` для надёжного
kill по порту, опционально). Пересобрать `vibe-workspace:dev`, пересоздать
контейнеры учеников (`docker rm -f vibe-<user>` → пересоздастся при входе;
workspace на bind-mount сохраняется). Сделать это управляемо (по одному или
скриптом), предупредив что активные сессии прервутся.

## Модель угроз / изоляция

- Приложение исполняется как `student` (uid 1000), `--cap-drop=ALL`,
  `--no-new-privileges`, лимиты 1.5G/1CPU — та же песочница, что и сейчас.
- Порты приложений **не** выставляются на хост; доступ только через панель с
  обязательным auth-гейтом.
- Прокси хост→контейнер по vibe-net (хост доверенный; контейнер↔контейнер
  по-прежнему заблокирован VIBE-FILTER в FORWARD).
- **Принятый риск:** HTML/JS ученика грузится на домене `vibe.kiselevgroup.com`
  (возможен XSS/фишинг между учениками, общий cookie-домен). Приемлемо для 5-10
  доверенных платных учеников; отметить в CLAUDE.md. Митигировать можно позже
  поддоменами (`<user>-<project>.vibe...`) — вне рамок MVP.

## Что НЕ входит (YAGNI)

- Поддомены вместо подпути.
- Кастомные домены, HTTPS-сертификаты на приложение.
- Билд-степы (webpack/vite); публикуем как есть (dev-сервер/статик).
- Редактор `publish.cmd` в UI (поле есть в конфиге, UI — потом).
- Мониторинг ресурсов/крон-перезапуск упавших приложений (только self-heal при заходе).
