## 2026-10-02 (третья сессия тем же днём)

- **Донастройка и критический фикс оси X графика «Нагрузка на процессор».**
  Пользователь прислал те же 6 референсных скриншотов Timeweb с просьбой
  привести подписи оси X в соответствие — редизайн прошлой сессии сделал
  график похожим внешне, но тики ещё не вели себя как на дашборде.
  - Переписана логика тиков в `app.js`: `vpsCpuFmtAxisTime` теперь
    показывает дату+время для `week`/`2w`/`month` (было только дату);
    добавлен алгоритм «красивых» тиков с нуля — `VPS_CPU_TICK_TARGETS`,
    `VPS_CPU_STEP_CANDIDATES_MS`, `vpsCpuNiceStepMs` (ближайший шаг к
    идеальному, не округление вверх — первая версия давала нехватку тиков
    на неделе/2 неделях, поймано на синтетических тестах), `vpsCpuFloorToStep`
    (выравнивание на локальную границу минуты/часа/полуночи),
    `vpsCpuBuildTicks` (сама сетка, анкор от последней точки назад, чтобы
    не терять самый важный тик у «сейчас» — тоже найдено на синтетике).
    Коммиты `4a5c5cc`, `39f3e9d`.
  - Пользователь сообщил о реальном баге на живой модалке: период «Месяц»
    показывал подписи с верным форматом (дата+время), но диапазон данных
    укладывался в ~20-24 часа вместо месяца. Диагностика по слоям (прямой
    вызов `getVpsMetrics('month')` → backend верен; прогон своих функций
    тиков на реальных данных → фронтенд-логика тиков верна) нашла
    настоящую причину в `panel/server.js`: роут `GET /api/vps-metrics`
    валидировал `range` по устаревшему хардкоженному списку без `'2w'`/
    `'month'` — эти запросы тихо откатывались на `24h` на сервере, а
    фронтенд всё равно подписывал по исходному range. Фикс: экспортирован
    `VALID_RANGES` из `vps-metrics.js` (единый источник вместо дублирующего
    списка), `server.js` переведён на него; `vibe-panel` перезапущен
    (процессный код, не статика). Коммит `70dc9e9`.
  - Пользователь подтвердил **«все работает»** — первая живая визуальная
    проверка графика CPU в браузере за всё время. Подтверждён явно
    диапазон «Месяц»; остальные пять используют тот же код, отдельно не
    комментировались.
  - Все три коммита запушены на `origin/master` вручную в процессе сессии.
