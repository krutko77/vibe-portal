## 2026-08-26

- Дополнительно (та же сессия): пользователь спросил, почему в контекстном
  меню проводника Windows пропал пункт «Открыть с помощью Code» после

  VS Code тем же user-setup поверх текущей версии с отмеченными галочками
  контекстного меню; чисто клиентский Windows-вопрос, к vibe-portal
  отношения не имеет, действий на сервере не было.
- Саппорт: у krutko77 (admin) не подключался десктопный VS Code по SSH к
  `vibe-krutko77` — `Extension 'ms-vscode-remote.remote-ssh' CANNOT use API
  proposal: terminalRemoteResolver`. Разобрано и **исключён vibe-portal** —
  причина внешняя, баг версии `0.126.0` расширения Microsoft Remote-SSH
  (github.com/microsoft/vscode issue #329735, вернулся 26.08 после закрытия
  25.08). Перепробованные тупиковые пути (переустановка расширения,
  `--enable-proposed-api`, откат VS Code 1.134.0→1.133.0) не помогли, т.к.
  дело не в редакторе; настоящий фикс нашли через комментарии к issue —
  откат расширения на `0.124.0` (`code --uninstall-extension
  ms-vscode-remote.remote-ssh && code --install-extension
  ms-vscode-remote.remote-ssh@0.124.0 --force`) + выключить автообновление
  именно у этого расширения. Подключение восстановлено и проверено.
  Изменений в коде/конфигах vibe-portal не было — чисто клиентская
  проблема, задокументирована в `docs/state.md` на случай повтора у других
  учеников.

## 2026-08-11

- Починен блокер Chromium/Playwright в контейнерах учеников: базовый образ
  `vibe-workspace:dev` не содержал системных библиотек под headless-браузеры
  (`libnss3`, `libX11.so.6`, `libasound.so.2` и ~17 других), а sudo внутри
  контейнера нет — ученик/агент не мог доустановить их сам. Найдено на
  примере личного проекта admin'а `website-customizer`
  (`webapp-testing`/`playwright-skill`, установленных для правок сайтов).
  Правка — `workspace-image/Dockerfile`: `RUN npx -y playwright@latest
  install-deps chromium` от root на этапе сборки (не хардкод списка пакетов
  руками — `install-deps` сам знает нужный набор под Debian 12, не привязан
  к версии `playwright` в конкретном проекте). Образ пересобран, фикс
  проверен реальным запуском Chromium в свежем контейнере (не по наличию
  файлов), живой контейнер `vibe-krutko77` пересоздан по запросу
  пользователя.
- Инцидент по пути: пересборка образа дважды роняла `/` (24G, единственный
  раздел хоста) в 0 свободного места. При втором падении (обрыв на
  распаковке слоя) тег `vibe-workspace:dev` временно указывал на битый,
  не до конца распакованный образ — рабочий образ уцелел только потому, что
  на его id ещё ссылался живой контейнер. Устранено чисткой (`docker builder
  prune -af`, `journalctl --vacuum-size=200M`, `npm cache clean --force` +
  `rm -rf ~/.npm/_cacache`, затем ещё раз `docker builder prune -af` после
  успешной сборки + хостовые кэши `ms-playwright`/`code-server`/`node-gyp` +
  `apt-get clean`) — итог 221M → 12G свободно. Заголовки не текущего ядра
  (`linux-headers-6.8.0-137*`, не запущенное сейчас `6.8.0-136`) намеренно
  не тронуты — пользователь попросил не удалять.
- `docs/state.md`/`docs/last-session.md`/`docs/handoff.md` самого проекта
  `website-customizer` этой сессией не обновлялись (отдельный git) — блокер
  там всё ещё формально числится открытым, хотя фактически решён на уровне
  платформы.

  `systemd/vibe-deploy.service`, код в `deploy-service/`) — узкий сервис по
  образцу `anthropic-shim`, позволяющий агентам в личных проектах admin'а
